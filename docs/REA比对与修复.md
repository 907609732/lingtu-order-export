## 差异及已落实行为

| 项目 | 原版可确认行为 | 0.1.5 修复 |
| --- | --- | --- |
| 淘宝日期 | `OrderFilter`，condition 中双层 JSON 日期，完整月份 | 按所选范围逐月请求，使用中国日期字符串，再按精确日期过滤 |
| 淘宝分页 | `hasMore`、`nextPageIndex`，旧结构 fallback | 使用平台返回页码；持久保存待请求月份/页码；重复页、空总数及结构异常停止并保留记录 |
| 淘宝商品 | 按 hierarchy 订单树、子订单号和 SKU 区分 | 排除孤立节点；同商品不同规格不合并；迁移旧版重复子订单行 |
| 淘宝金额 | `actualTotalFee` 为商品行合计 | 多件商品单价不再误填行合计；导出新增商品ID、子订单号、SKU ID、商品实付合计 |
| 拼多多列表 | 专用 `order_list_v4` POST；offset 从字符串 `0` 开始，page 恒1、size30 | 独立采集器，保存 offset；依据短页/日期边界结束；未知结构、循环 offset 报错 |
| 拼多多会话 | 官方 Cookie 中当前用户与 AccessToken | 只读本软件官方会话，在固定官方域内请求；任务绑定账号摘要，换号停止，日志不包含凭证 |
| 拼多多详情 | 官方 `order.html` 的 `window.rawData.data` JSON | 逐单读取并按 orderSn 绑定；只解析 JSON，不执行页面脚本；补收货、物流和金额字段 |
| 拼多多组合单 | 顶层订单ID、嵌套商品、组合日期及分单位金额 | 保存多商品、保留不同明细；未知组合详情继续标缺项 |
| 执行反馈 | 采集、分页、详情阶段 | 淘宝日志增加年份/月/页，拼多多增加真实分页和详情处理进度；设置开关保持可用 |

实现根据上述协议和字段合同独立编写，没有将商业应用业务代码复制进产品。原版忽略证书错误、弱隔离等设置不属于需要复现的订单合同；现有 Electron 隔离继续开启。

## 验证与限制

- 真实淘宝只读核对：旧列表中的已知订单在新月份请求中再次找到；请求 `SUCCESS`，识别1笔，日期/商品/金额有值，全部处于请求月份，分页正常结束；原有任务数量和订单数量未改变。
- 隔离桌面测试：淘宝跨月、跳页、服务错误中断后从保存页续采、精确日期过滤；拼多多初始/后续 offset、失败续采、详情绑定、换号阻止、匿名会话提示；订单和凭证不进入日志。
- 单元测试包含长订单号、SKU、金额单位、旧数据迁移、组合单、HTML JSON 边界、空总数和循环页码。另回归五个平台合成采集及实时日志。
- 尚未取得原软件同账号同日期的实际导出文件，不能声称逐行、逐列、图片及完整历史范围完全一致。历史本地缓存导出也不作为原软件内置导出格式的证据。
- 淘宝详情字段仍待官方页响应样本核对；拼多多当前真实登录会话和完整历史范围仍待验收。普通详情标记已处理也不意味着平台未返回的付款方式、备注等字段已补齐；不返回的值保留空白/缺项，任务保留“待核对”。
- 所有原软件静态观察、合成测试和我方真实请求结果分开记录，避免把源码可见误写成线上成功。
